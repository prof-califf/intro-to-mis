Optional · Extra credit

SQL for Business: From One Query to Real Analysis

About 3 to 5 hours, at your own paceBuilds on Lab 7 →

Lab 7 showed you that you can ask a database a question. One week is enough to learn that, and not enough to learn what analysts do with SQL every day. This bootcamp is the rest of it: joining several tables at once, grouping and filtering groups, working with dates, labeling rows, breaking a hard question into steps, and comparing each row with the ones around it. You work on the same Cascadia database, in your browser, with nothing to install.

WhyWhy SQL is worth a weekend

Almost every company keeps its operating data in databases, not spreadsheets. Sales, inventory, customers, payroll, website clicks: systems write them to tables like the ones in Lab 7, all day. A spreadsheet is a copy someone exported, already shaped by what they guessed you would ask. SQL is how you ask the database yourself.

That changes your work in three ways. You stop waiting. A question that would take a request to IT and a week can take five minutes. You can check. When two reports disagree, you can go to the source and find out why. You can ask what nobody planned for. Most useful findings come from questions no report was built to answer, like Lab 7's sales with no member attached.

SQL is also unusually durable. It has been the common language of databases since the 1970s, and it is still how you query cloud data warehouses and many analytics tools. What you learn here carries over, with small changes, to most of the systems you will meet.

Where you would use it

Marketing: which customers bought once and never came back. Finance: why this month's revenue report and the accounting system disagree. Operations: which stores are below their reorder point right now. HR: turnover by department and manager. Each one is a query or two.

The SQL cheat sheet: every word this lab uses, plus a few more, all runnable


Every example below runs in the sandbox as written. The four groups are the order the lessons use them
in. Come back here whenever a word looks unfamiliar.


1. Getting data out: SELECT and FROM. Every query starts with these two. The star
means all columns; naming columns keeps the result narrow; DISTINCT means each value once.


SELECT * FROM stores;
SELECT store_name, region FROM stores;
SELECT DISTINCT category FROM products;


2. Keeping some rows: WHERE. Compare with =, >, <, and <> (not equal).
LIKE matches a pattern, where % means "anything here." AND needs both conditions true; OR needs either.
Text goes in single quotes; numbers do not.


SELECT product_name, list_price FROM products WHERE list_price < 30;
SELECT product_name FROM products WHERE product_name LIKE 'Ridgeline%';
SELECT COUNT(*) FROM sales WHERE store_id = 4 AND quantity > 2;
SELECT COUNT(*) FROM sales WHERE store_id = 5 OR store_id = 8;


3. Sorting and stopping: ORDER BY and LIMIT. ORDER BY sorts smallest first unless
you add DESC. LIMIT stops after that many rows, and it always goes last.


SELECT product_name, list_price FROM products ORDER BY list_price DESC LIMIT 5;


4. Adding things up: COUNT, SUM, AVG, MIN, MAX, and GROUP BY. On their own, these
turn a whole table into one number. Add GROUP BY and you get one number per group, which is a pivot
table in words.


SELECT AVG(list_price) FROM products;
SELECT MIN(list_price), MAX(list_price) FROM products;
SELECT category, COUNT(*) FROM products GROUP BY category;
SELECT store_id, SUM(quantity * unit_price) FROM sales GROUP BY store_id;


Then JOIN, which Steps 5 and 6 teach on their own, because it is the one idea here
with no spreadsheet equivalent.
